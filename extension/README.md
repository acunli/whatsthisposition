# what’sthisposition for Chess.com and Lichess (browser extension)

Finish a game on Chess.com or Lichess and a card pops up in the bottom-right corner of the page (the toolbar popup's **Open the card by itself when a game ends on** has **Chess.com** ticked to begin with and **Lichess** to tick, which the browser asks about first; untick a site and the extension leaves its pages alone). (For a past game, open it and click the extension's button in the toolbar, then **Review this game**: that works on both sites whatever is ticked.) Press **Analyze** in the card and the game is reviewed on your own computer: both players' accuracy and how many Brilliant, Great, Best… Blunder moves each made. **See every move explained** then opens the full step-by-step review on what’sthisposition, carrying the finished review with it, so the website shows it at once instead of searching again.

Tip: pin the extension (the puzzle-piece icon → the pin) so its button is always in the toolbar.

**[Add it to Chrome from the Chrome Web Store](https://chromewebstore.google.com/detail/bngblpcelnjnhbmaljgelkddkfhjneka)** (free; also works in Edge, Brave, Opera and other Chromium browsers).

## Build it from source (unpacked)

```bash
npm install
npm run ext:build          # builds extension/dist
```

1. Open `chrome://extensions` and switch on **Developer mode** (top right).
2. Select **Load unpacked** and choose the `extension/dist` folder.
3. Play a game on Chess.com, or on Lichess after ticking **Lichess** in the toolbar popup: the card opens when it ends. Or open a finished game and click the extension's toolbar button (this works without the ticks).

### Testing the automatic card

- After **Reload** in `chrome://extensions` there's no need to reload the Chess.com and Lichess tabs: the extension adds its script to them again (Lichess tabs only while Lichess is on), and the old copy stops.
- Play any game (a 1-minute game, or one against the computer). The card should open within about a second of the result appearing.
- Each game's card opens once: reloading the page doesn't open it again (the toolbar button still does).
- The toolbar popup says what the page is doing ("Watching this game: the card opens when it ends").
- To see each step, open DevTools on the game's tab, set the console's level to include **Verbose**, and filter on `what’sthisposition`: it logs the game's id, the site's answers, when the game ended and why the card opened (or why not).

It works in any Chromium browser (Chrome, Edge, Brave, Arc, Opera). Firefox has its own build: see [Firefox](#firefox).

## Publish it on the Chrome Web Store

1. `npm run ext:zip` builds `extension/whatsthisposition-extension-<version>.zip` (the version comes from `package.json`).
2. Register at the [Chrome Web Store developer dashboard](https://chrome.google.com/webstore/devconsole) (a one-time $5 fee) and select **New item**, then upload the zip.
3. Fill in the listing:
   - **Single purpose:** "Reviews a finished Chess.com or Lichess game: accuracy and move labels, with a link to a full explanation."
   - **Permissions:** `offscreen` ("Runs the Stockfish chess engine in a hidden extension page to review the finished game on the user's computer"), `activeTab` and `scripting` ("When the user clicks the toolbar button on a Chess.com or Lichess tab, finds the game on that page and opens the review card there; after an install or update, adds the extension's script to Chess.com and Lichess tabs that were already open, so the card works there without a reload; when the user turns Lichess on, runs the extension's script on Lichess pages"), `storage` ("Remembers whether the automatic review card is on, and which games' cards have already opened, so reloading a page doesn't open one again"). It runs on `https://www.chess.com/*`, where it reads the page's own game data (the JSON Chess.com's game page loads) to get the moves, and on request reads the signed-in player's public game list from `api.chess.com`; and on `https://lichess.org/*`, if the user turns Lichess on, where it reads the finished game from Lichess's game export.
   - **Host permissions** (`https://www.chess.com/*`, for the content script and `host_permissions`; `https://lichess.org/*`, an optional host permission asked for only when the user ticks **Lichess** in the popup): watches the game on the page to open the review card when it ends; reads the finished game's moves from the page or Chess.com's own game data, or from Lichess's game export (`lichess.org/game/export/{id}`) once the game is over; adds its script to tabs that were open before an install or update; and if the page names no game, reads the signed-in player's public game list (`api.chess.com`, `lichess.org/api/games/user/…`). The install warning is the Chess.com content script's ("Read and change your data on www.chess.com"); the browser asks about lichess.org only when the user turns Lichess on.
   - **Why Lichess is opt-in.** A site added to `host_permissions` or a content script is a new permission: Chrome disables an installed copy on that update until its user accepts it (the extension's menu shows "Re-enable"), and Firefox asks before updating. So `lichess.org` is in `optional_host_permissions`, and 1.0.7 updates without asking anything. The popup's **Lichess** tick asks for it (Chrome may close the popup while it asks; the background finishes the job); with it, `src/lichessAccess.ts` registers `lichess.js` for Lichess pages (`scripting.registerContentScripts`) and adds it to the Lichess tabs already open. Unticking it takes the permission back and removes the script (open Lichess tabs keep their copy until they reload); so does removing the site in the browser's extension settings. Without it, the toolbar button still reviews the game in the current Lichess tab (`activeTab`).
   - **Remote code:** no. All the JavaScript and the Stockfish WebAssembly are in the package; only game data (JSON) comes from Chess.com and Lichess.
   - **Privacy policy:** `https://www.whatsthisposition.com/credits#privacy` (it has a paragraph on the extension).
   - **Data usage:** it collects nothing: tick none of the data types, and tick the three certifications. The analysis runs on the user's computer; the review link carries the game in the URL's fragment (`#review=…`), which is never sent to a server.
   - **Store listing:** everything is in [`store/`](store): the description (`description.txt`; its first lines and the manifest's `name` and `description`, the listing's title and summary, carry what people search the store for: chess game review, analysis, Chess.com, Stockfish, accuracy; but no lists of names: 1.0.3 was rejected as "excessive keywords" (Yellow Argon) for a list of browsers, so name things in sentences, not lists), the store icon (`icon-128.png`, 96×96 artwork with 16 px of transparent padding), four 1280×800 screenshots and the small (440×280) and marquee (1400×560) promo tiles, all JPEG without alpha as the store asks. Category Games, language English, homepage `https://www.whatsthisposition.com`, support `https://github.com/acunli/whatsthisposition/issues`.
4. Submit for review. Updates: bump `version` in `package.json`, `npm run ext:zip`, upload.

The review link opens `https://www.whatsthisposition.com` (the site's primary address; the bare domain redirects there, keeping the `#review=…` part). `EXT_SITE_URL=https://whatsthisposition.vercel.app npm run ext:zip` points it at another address, e.g. a preview deployment.

## Firefox

`npm run ext:firefox` builds Firefox's version into `extension/dist-firefox` and packs `extension/whatsthisposition-firefox-<version>.zip`. The code is the same; only the background differs: Firefox's background is an event page rather than a service worker, so it starts Stockfish's workers itself (`src/background-firefox.ts` runs `src/engine.ts`), and Firefox has no `offscreen` permission or engine page. The manifest gets `background.scripts`, `browser_specific_settings.gecko` (id `extension@whatsthisposition.com`, Firefox 128 or later, `data_collection_permissions: none`) and a name within addons.mozilla.org's 45 characters ("Free Chess.com game review & analysis").

- **Try it:** `about:debugging#/runtime/this-firefox` → **Load Temporary Add-on…** → pick `extension/dist-firefox/manifest.json`. Checked on Firefox 154: the card opened by itself on a game that had just ended and **Analyze** reviewed it (78 plies at Fast in about 20 s).
- **Lichess** is opt-in here too (`optional_host_permissions`, Firefox 128 and later): the popup's **Lichess** tick asks for it, and it also shows as a switch in the add-on's **Permissions** tab in `about:addons`.
- **`npx web-ext lint -s extension/dist-firefox --self-hosted=false`:** no errors; 7 warnings about `innerHTML` in `panel.js`/`content.js`, where every value from a game is escaped (`esc()`) and the rest is the extension's own markup.
- **Publish:** sign in at [addons.mozilla.org's Developer Hub](https://addons.mozilla.org/developers/) (free) → **Submit a New Add-on** → **On this site** → upload the zip. The bundle is minified, so AMO asks for the source: upload a zip of the repository (or `git archive -o source.zip HEAD`) and say how to build it: "`npm ci`, then `npm run ext:firefox`; the add-on is `extension/dist-firefox` (Node 20+)". Listing: the same description (`store/description.txt`) and screenshots, slug `whatsthisposition`, category Games & Entertainment, support site and privacy policy as for Chrome. Data collection: none.

## Fair play

On **Lichess**, the page script never reads the moves on the page (Lichess renames its move list's tags now and then, on purpose, to stop cheating tools). It looks only at whether the game's page shows the end (`.result-wrap`: the result under the moves; `.follow-up`: the buttons after a game), asks Lichess nothing about a game until then, and reads the game from Lichess's export only once the export says it's finished. The toolbar button on a game still being played says so without asking Lichess.

On **Chess.com**, the card opens only once a game is **over**: when the page shows the result under the moves, or Chess.com's own game data says `isFinished`. The moves are read only then, and nothing is analysed until you press **Analyze**, so a game in progress is never analysed. That is the same as reviewing a game on Chess.com afterwards.

It never touches Chess.com's own scripts: the board's JavaScript API (`wc-chess-board`'s `game`) has a `CheatDetectionError` listener, and an extension calling it during a game would look like a cheating tool. The page script only reads the page (how many moves the list shows, and the result), and asks Chess.com for a live game's data at most once while it's played, plus a backstop every 60 s (30 s when no move list shows); a live game answers 404 until it ends.

## How it works

- **`src/popup.ts`** is the toolbar button's popup. It asks the Chess.com or Lichess tab which game is there and, on **Review this game**, asks it to open the card. If the tab has no script (opened before the extension, or Lichess not turned on), it adds the script to it first (`activeTab` + `scripting`). Under **Open the card by itself when a game ends on**: **Chess.com** (ticked unless its user takes it off; stored as `chesscom`, and until it is first changed read from the older single switch `auto`, so whoever had turned the card off keeps it off) and **Lichess** (asks for or gives back the optional `lichess.org` permission).
- **`src/lichessAccess.ts`** keeps the Lichess script in step with that permission: registered (`scripting.registerContentScripts`) and added to open Lichess tabs while it's granted, removed when it's taken back. The background runs it after an install or update, at start-up and whenever the permission changes (`permissions.onAdded`/`onRemoved`).
- **`src/card.ts`** is what both page scripts share: the card in its iframe (the panel is told which site it's on, `panel.html?host=…`, and talks only to that page), the popup's questions, whether the site's games are watched (on Chess.com the `chesscom` setting: off, the script doesn't look at the page or ask Chess.com anything, but still answers the toolbar button; on Lichess the permission itself decides whether the script runs), the games whose card has opened, and stopping when a newer copy of the script arrives.
- **`src/lichess.ts`** runs on Lichess (while Lichess is turned on, or once the toolbar button is clicked on a Lichess tab) and opens the card when a game played or watched on its own page (`lichess.org/game/{id}`, `/game/{id}{player}`, `/game/{id}/black`, and the older addresses without `/game`) ends. A game counts as played here when its page is first seen without the end (`.round__app` drawn, with `.round__app__table`, and no `.result-wrap` or `.follow-up`); when the end appears it asks Lichess's export for the game (retrying for a few seconds if it's not marked finished yet) and opens the card at once if the result shows. A game opened already finished gets the card by itself only if it ended in the last 10 minutes; aborted games and variants (`.round__app.variant-…`) get none, and nothing is asked. The board's side (`.cg-wrap.orientation-black`) sets which side the review is from. The toolbar button finds the game from the address, the finished game's analysis button, or the signed-in player's newest game (`body[data-username]`, `/api/games/user/…?max=1`). Not on Lichess TV (`/tv`), whose address names no game.
- **`src/content.ts`** runs on Chess.com and opens the card when a game ends. It watches two things, either of which is enough:
  - **The move list on the page** (`wc-simple-move-list`: a `.node.main-line-ply` per move, then `.game-result` with "1-0" when it's over). `MoveListWatch` (`src/lib/review/chesscomPage.ts`) calls a game live once moves are seen being added (or it has shown no result for 8 s), so a game opened already finished doesn't count; its end is the result appearing. This needs no game id, so it works on `/play/online` and against the computer too.
  - **Chess.com's game data** for the game named by the address or, once it's over, the Game Review button: 404 while a live game is played, then `isFinished`. A game opened within 10 minutes of its end also opens the card.

  The card shows Chess.com's copy of the game (full headers) if it arrives within 4 s, else the moves read off the page (figurine notation included), checked move by move with chess.js. Each game's card opens once (its id and moves are remembered in `chrome.storage.local`). A copy of the script left from before an update or reload stops itself when the new one starts. For the toolbar button it finds the game from, in order: the URL (`/game/live/…`, `/game/…`, `/game/daily/…`, `/analysis/game/…`); Chess.com's **Game Review** button, a link to `/analysis/game/live/{id}?tab=review` (in the result box and the side panel); the newest game linked on the page; and, if the page names none, the signed-in player's newest game from their public game list. It reads the game from Chess.com's game endpoint (`/callback/live/game/{id}`), which serves a live game only once it has ended.
- **`src/background.ts`** (the service worker) adds the scripts to open Chess.com and Lichess tabs after an install, update or reload, keeps the Lichess script in step with its permission, and opens the engine page on demand.
- **The card** is `panel.html`, an extension page in an iframe, so its scripts and styles are separate from the site's.
- **Stockfish runs in a hidden engine page** (`engine.html`, an offscreen document that `src/background.ts` opens on demand and closes when no card needs it). The card sits inside the chess site's page, and there the browser may refuse to start workers ("The engine failed to load"); the engine page is the extension's own, so it can. The card sends it searches over a runtime port (`src/remoteEngine.ts`) and falls back to workers in the card if the engine page can't open. If neither starts, the card says why and offers the review on the website instead.
- **`src/panel.ts`** decodes the moves (Chess.com's compact TCN encoding, `src/lib/review/chesscomGame.ts`) into a PGN and runs **the website's own review** (`src/lib/review`): Stockfish 19 in Web Workers (`engine/`), the same labels, the same accuracy formula and the same opening book (`data/`), at the same default depth (Standard, 14; Fast and Thorough are one click away). Critical moments are searched deeper, as on the site.
- **The link** opens `/#review=<PGN>&as=<your colour>&depth=<depth>&data=<review>`. `data` is the finished review (every position's depth, evaluation and engine lines, packed and gzipped by `packReview` in `src/lib/review/share.ts`; about 4–8 KB for a whole game), so the site shows the review at once without running Stockfish. All of it is in the URL's fragment, which is never sent to a server.

Everything is bundled from this repository by `build.mjs` (esbuild), so the extension and the site always label moves the same way.
